## Permanent implementation rule

MoolSocial keeps more useful capability by sharing production owners, not by
building a second app for every actor:

- one shared native action surface is reused wherever the customer task is the
  same;
- exact user/workspace type changes authoritative data, eligibility, terms,
  permissions, geography and failure handling through configuration or a thin
  policy adapter;
- exact actor/outcome tickets remain separate acceptance contracts, but their
  count does not create an equal count of screens, routes, services or builds;
- a new screen, route or backend owner requires written evidence that an
  existing owner cannot safely express the required interaction or trust
  boundary;
- legacy presentation stays read-only; existing tested non-UI owners are
  reused where their contracts remain valid; and
- dependency-held behavior remains visibly and technically held. It is never
  fabricated merely to make the schedule appear complete.

The founder's unified Buy rule is permanent for this MVP: Manufacturer,
Retailer, Distributor and every other eligible buyer use one native Buy main
action. Workspace context projects exact value-chain categories and commercial
authority; it does not create another catalogue, Cart, checkout, tracking,
bill or receipt family.
