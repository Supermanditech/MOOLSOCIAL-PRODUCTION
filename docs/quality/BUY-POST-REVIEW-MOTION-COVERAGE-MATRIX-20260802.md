## Prepared execution sequence

### R54 — existing `BUY-FV2-138`/`076`/`017`

1. Replace `_surfaceTransitionPhase` and `_BuySurfaceProgress` with one fixed
   body transition owner that animates only the newest genuine view tree. The
   mutable session is shared by every view, so retaining an outgoing tree could
   rebuild it against the successor state and expose stale/invalid business
   assumptions; incoming-only motion is the safe fixed-owner equivalent.
2. Let existing session mutators emit presentation-only `forward`, `back` or
   `replace` intent and a monotonic event id; these fields never decide routes,
   block callbacks, persist or cross process restoration.
3. Use a short shared-axis fade/translation for forward/back, crossfade for
   same-level replacement, zero duration under reduced motion, and no replay on
   unrelated notices, Cart arithmetic, lifecycle or repeated selected tabs.
4. Keep header, accepted Search, mini-Cart and dock out of the moving owner.

### R55 — existing `BUY-FV2-079`/`087`/`093`/`095`

1. Capture the tapped product media rectangle and immutable product id at the
   existing card owner, then animate one pointer-ignoring media overlay to the
   laid-out detail target. The session opens the product immediately.
2. Cancel safely if the product becomes invalid, geometry is unavailable,
   reduced motion is on, the app backgrounds or a second route wins.
3. Preserve one semantics owner throughout; the overlay is excluded from
   semantics and hit testing.
4. Add bounded pinch/reset to the gallery, retain horizontal page swipe, and
   consider a maximum 6 px scroll-linked media offset only if compact and
   profile evidence remains within budget.
5. Fade only the real decoded image frame over the existing product fallback;
   error fallback remains immediate and static.

### R56 — existing `BUY-FV2-076`/`030`/`089`/`099`/`117`/`123`/`133`

1. Add one scoped Buy modal route helper with finite arrival/reverse, stable
   focus/keyboard/Back ownership and immediate reduced-motion presentation.
2. Migrate one logical family at a time; do not broad-replace every Flutter
   modal call in one edit. Category motion (R40.3), Saved/Cart (R45) and
   Coupons/Offers (R46) keep their accepted owners unless their exact surface
   is the scoped family under test.
3. Use finite field/status transitions only on real validation, saved address,
   review/report, prescription, camera/manual-code or recovery state changes.
4. Never animate a simulated network wait, pharmacy approval, payment result,
   order placement or address validation.
