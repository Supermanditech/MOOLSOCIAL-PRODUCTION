## Founder-review sequencing

The Universal, Buy and Work authorization envelopes each retain an HTML
founder `FINAL` before new native Flutter states, followed by cumulative final
review. The founder has expressed a preference for only one final review after
non-stop execution.

To use one review only across all preauthorized work, approve versioned
sequencing amendments for all three manifests that delegate each new HTML
reference freeze after complete machine/human internal verification. Without
those amendments, Codex must pause for the applicable HTML founder `FINAL`
before each portfolio's native work. This sequencing choice changes review
timing; it does not waive accepted-reference, regression, build, device or
dependency gates.

prevents Buy/Work presentation from getting ahead of money, regulatory,
