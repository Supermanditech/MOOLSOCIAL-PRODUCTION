# UAW-R15 Personal copy fitment accessibility preselection assessment

Date: 6 August 2026
Ticket: `UAW-R15-PERSONAL-COPY-FITMENT-ACCESSIBILITY`
Classification: `mvp_required`

## Customer outcome and reason

Every current Personal exposure root, truthful projection state and legacy-
route recovery remains readable and operable across the founder-authorized
reference viewport/text-scale matrix.

## Reuse and smallest complete scope

- Reuse the R03 Personal Mool root, shared R06/R07/R08/R10 action-choice root,
  R13 projection-state panel and R12 containment screen without adding a new
  presentation owner.
- Reuse their existing native semantics, SafeArea, scroll, tap-target and
  reduced-motion behavior.
- Add one deterministic matrix suite for 320x568, 360x640, 360x720, 375x667,
  390x844, 412x915 and 430x932 at 100% and 140% text.
- Verify all copy is present without render overflow or max-line truncation,
  all actions retain at least 44x44 targets, semantics name every action, and
  callbacks remain operable at compact 140% text.

Necessity proof: R03 and R06 include representative fitment rows, while the
later Ride/Book/Work configurations and R12/R13 recovery states do not yet have
one exact cross-owner matrix. One acceptance suite over existing owners is the
minimum complete work; a new screen or accessibility wrapper would duplicate
production presentation before evidence shows a defect.

## Explicit exclusions

- No copy rewrite, layout change or production accessibility wrapper unless
  the deterministic matrix first proves a defect.
- No artificial text-scale cap, hidden action, omitted truthful state or
  semantics substitution.
- No keyboard/IME claim for these non-input exposure/recovery surfaces.
- No screenbook/HTML, legacy Universal, vertical, backend or external-service
  change.
- No build, install, OPPO mutation, credentials, commit, push, deploy,
  promotion or FIX7/baseline change.

## Dependencies, approval and verification

Dependencies: founder-preauthorized batch, completed R01-R14 Personal owners,
founder-defined reference matrix, native Flutter directive and 60–75 day reuse
lock.

Verification: execution gate; exact matrix/config identity; 14 viewport/text
rows across five roots, six R13 states and six R12 recovery reasons; compact
semantics/44x44/operability; full analyze; shared regressions; protected-state
diffs; no build/device action.

Estimated batch impact: **1 day**, within the locked delivery window.

## First matrix disposition

The first deterministic run proved one production defect: at 320x568 and 140%
text, the shared two-line supporting-copy limit truncates Work's “Find
verified, funded work near you” phrase. The R15 execution gate was therefore
expanded only for the minimum shared correction: remove that limit from the
existing scrollable action card. No new presentation owner is warranted.

The compact semantics run then proved one second shared-owner defect:
standalone Pay recovery presents two indistinguishable `Open Mool` actions
because its current owning root is already Mool. The same bounded disposition
therefore suppresses only that redundant secondary action; the other recovery
reasons retain distinct owning-root and Mool actions.
