# C33B C33A shared C17D owner lifecycle binding

The first final C33B chain passed regression memory, MVP scope/delivery, UI
locks and C32X, then stopped at C33A because its gate unconditionally pinned
C17D's pre-C33B failure hash. C33B is explicitly authorized to migrate that
separate owner after C33A preserved its 0-pass/10-fail state.

C33A's machine state remains the authority for the historical failure hash.
Its executable gate must require that hash only while C33A is active;
otherwise it must accept C33B's exact final hash only through an active C33B
assessment or a preserved qualified C33B assessment. REG-2304 must be
registered before repair or replay.

## Result

REG-2304 was registered before repair. C33A now preserves its historical
C17D failure hash in machine evidence, while its executable gate requires the
exact C33B final hash through active or preserved C33B scope. C33A and C33B
then passed on PowerShell 7 and Windows PowerShell.
