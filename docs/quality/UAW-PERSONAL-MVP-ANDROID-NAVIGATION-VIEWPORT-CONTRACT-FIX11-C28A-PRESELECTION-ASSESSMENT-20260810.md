# C28A preselection — Android navigation viewport contract

Classification: `mvp_required`.

Customer outcome: one evidence-backed contract identifies and bounds the shared
Android window/rail ownership correction required before another OPPO review.

## Reuse and duplicate search

- Reuse `MoolDestinationNavigationV2`, `MoolGlobalNavigationV2`,
  `_MoolFamilyRootButton`, `_MoolHomeLauncher` and
  `MoolLocalNavigationRail`.
- Reuse every existing family catalogue, route, feature screen, session,
  controller, service, copy owner and C27 visual token.
- All six founder-facing projections already converge on the same shared
  destination shell; no feature-local rail or route is necessary.
- `MainActivity` contains no existing system-UI/inset compatibility owner. One
  bounded Android window owner is necessary because Flutter host semantics
  cannot configure or prove the OPPO window/accessibility viewport boundary.
- Create no screen, route, backend owner, action, label, theme or feature state.

## Robustness and delivery fit

The work fixes one confirmed launch accessibility/navigation regression by
configuration and a thin platform adapter around shared presentation. It keeps
the approved 58px rail, one-tap actions, keyboard recovery, reduced motion,
Back/Mool/Chat continuity and the installed r60.26 audit identity. Estimated
impact is two days and remains inside the founder's 60–75-day lock.

## Boundaries

C28A is reference-only. It records the root contract and selected owners. It
does not authorize Flutter/Android runtime mutation, test/gate mutation, a
build or an install.
